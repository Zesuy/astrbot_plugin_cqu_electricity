# 重庆大学宿舍电费插件 (astrbot_plugin_cqu_electricity)

面向 **AstrBot 4.28.1+** 与 **OneBot 11 / NapCat**（aiocqhttp 平台）的重庆大学宿舍电费查询、自动化监控与多用户管理插件。每个 QQ 账号全局绑定一个宿舍，同宿舍用户共享采集记录与用量分析；提供本地渲染的七日电费趋势看板图片、自然月与充值周期的用电日历、余额与可用天数互斥预警提醒，以及专供大模型（LLM）调用的本人只读与自服务工具集。

## 1. 项目介绍与定位

- **插件标识**：`astrbot_plugin_cqu_electricity`
- **显示名称**：重庆大学宿舍电费
- **定位**：校园生活实用型 Bot 插件。针对重庆大学校方缴费平台缺乏结算标记、虎溪与沙坪坝跨校区字段非对称、同宿舍室友重复抓取触发风控、早间扣费容易阻断剩余天数预测等核心痛点，为在校学生提供低频、高可靠、免骚扰的宿舍电费管理服务。沙坪坝老校区支持校方能源管理系统直连，免密提供电表累计读数、今日用电区间与月度账单统计。
- **当前版本**：`v0.1.17`
- **底层架构**：SQLite 3（Schema 5，WAL 模式与外键约束），支持平台限定为 `aiocqhttp`。

## 2. 快速上手与配置指南

- **Python**：`>= 3.11`（推荐 `3.12+`）
- **AstrBot**：`>= 4.28.1, < 5`
- **消息平台**：`aiocqhttp`（NapCat / OneBot 11）
- **权限说明**：安装与修改全局配置需 AstrBot 管理员权限；普通用户仅能绑定本人宿舍及管理个人提醒。

### 2.2 安装流程

1. **下载安装包**：下载发布页的标准插件 ZIP 包（或将插件代码打包为 ZIP）。
2. **WebUI 原生上传**：以管理员身份登录 AstrBot WebUI → **插件管理** → **从文件安装**，上传插件 ZIP 即可。
   - 更新插件同样直接上传新版本 ZIP，由 AstrBot 管理生命周期与热重载，**无需提前卸载或删除已有业务数据**。

### 2.3 认证配置指南（二选一）

> [!NOTE]
> **校区认证差异说明**：
> - **沙坪坝校区（A/B/C校园）**：默认启用校方能源管理系统直连（`shapingba_nh_enabled: true`），**无需配置 Token 即可免密查询**沙坪坝宿舍的实时余额、累计电表读数、今日用量与本月账单；若同时配置了 Token，在能源系统异常时可自动降级至缴费平台。
> - **虎溪校区**：需依下文指引配置重庆大学缴费大厅 `access_token`。

#### 方法一：一键 WebUI 配置法（首选推荐）

无需在服务器上管理文件，直接在浏览器中取得访问令牌并粘贴至 WebUI：

1. 打开[重庆大学缴费大厅](https://payment.cqu.edu.cn/plat/shouyeUser)，完成统一身份认证登录；
2. 登录成功后，按 `F12` 打开浏览器开发者工具：
   - **方式 A（控制台获取）**：切换到 `Console`（控制台）面板，输入并执行：
     ```javascript
     sessionStorage.getItem('access_token')
     ```
   - **方式 B（存储面板获取）**：切换到 `Application`（应用）→ `Storage` → `Session Storage` → `https://payment.cqu.edu.cn`，直接复制 `access_token` 的值；
3. **直接粘贴配置**：
   - 复制取得的内容，进入 AstrBot WebUI → **插件配置** → `astrbot_plugin_cqu_electricity`，粘贴到 `session` 配置项并保存。
   - **自动剥离外层引号**：控制台输出若带有外层单引号 `'...'`、双引号 `"..."`、中文引号 `‘...’`/`“...”` 或 `Bearer ` 前缀，**均可直接原样粘贴**，插件在读取凭据时会自动剥离外层引号与首尾空白。

#### 方法二：私有文件配置法（进阶 / 无头 / 自动化运维）

若需配合定时刷新脚本或在无图形界面环境下运行：

1. 保持 WebUI 中的 `session` 配置项为空；
2. 插件将自动回退读取 `token_file` 指定的本地 JSON 文件（留空则默认读取插件数据目录下的 `data/plugin_data/astrbot_plugin_cqu_electricity/auth.json`）；
3. 文件格式参考 `auth.example.json`：
   ```json
   {
     "access_token": "your_cqu_payment_session_token_here"
   }
   ```
4. 插件在每次发起网络采集时动态加载该文件，文件更新后即时生效，无需重启 AstrBot 进程。

## 3. 为什么做深度定制

开源社区原有的电费脚本或原型主要面向个人单次命令行查询，在实际投入 QQ 群与多用户机器人长期稳定运行时存在以下严重缺陷：

1. **同宿舍重复并发与请求聚合**：
   一个宿舍多位室友同时在群聊中查电费，若各自向校方接口发起 HTTP 请求，容易受到校方网关限流与访问频次限制，并引发状态竞争。我们通过全局房间映射与 SQLite 集中持久化，实现同宿舍数据共享；同时通过内存级在途任务合并（In-flight Merging），同宿舍秒级并发查询合并为单次底层请求。
2. **校方无扣费标记与早间预测阻断（v0.1.15 重点修复）**：
   校方缴费大厅每天上午执行电费扣除，但接口只更新余额数字，完全没有结算流水或扣费状态位。早期版本在上午检测到余额变动时，会误判为“数据突变/不可信”，从而强行隐藏天数预测；v0.1.15 引入保守的扣费特征匹配算法，彻底解决了早间刚扣费就查不到天数的问题。
3. **两校区数据结构异构与楼栋命名规范化**：
   - 虎溪校区通过缴费平台提供电表累计读数和电价，可通过前后读数差精确计算用量；
   - 沙坪坝老校区（A/B/C校园）全面接入校方能源管理系统直连，免密直接读取精确电表累计读数、今日 00:00 至最新节点的 6 小时间隔用电统计与当月累计账单；在接口回退或传统缴费平台模式下，亦支持由余额净扣减推算；
   - 楼栋存在“幢/栋/舍/单元/负层”等复杂口语化称呼（如“梅园七幢”与“梅园7栋”、“A区12舍3单元112”、“负339”等），定制了多候选消歧算法，唯一定位才允许绑定。
4. **错峰排程与散列调度**：
   引入 09:00 / 14:00 双时段定时批次，基于宿舍 ID 散列错峰调度，在 5 分钟窗口内均匀分段并叠加 0～10 秒微扰动，相邻宿舍保持至少 10 秒硬间隔，平滑整点并发请求。
5. **私聊白名单与运行时权限豁免**：
   AstrBot 4.28.1 的严格白名单机制默认会阻断未配置的私聊消息。插件在白名单生命周期注入可撤销的专用例外，仅放行电费相关的前缀命令，既保护私聊私密性，又无需放开全局私聊。

### 4.3 大模型（LLM）Function Call 工具一览

插件向 AstrBot 注册了 8 项标准函数工具。调用身份直接从消息底层事件读取，严禁且无法通过大模型参数伪造他人身份：

#### 只读查询工具（不触发外网请求，直接读本地 SQLite）
1. `get_my_electricity()`：读取提问者当前绑定宿舍的最新平台余额与用量。上午时段可一并返回假设扣费后余额；严格区分实际、预计与不可用状态。
2. `get_my_electricity_history(days=7)`：查询 1～30 天的历史每日概览、日均读数增量与逐次采集明细。

#### 本人自服务操作工具（需严格由用户本人意图驱动调用）
3. `bind_my_electricity(room)`：由大模型解析用户自然语言后执行宿舍绑定，经过校方接口校验唯一定位后落库。
4. `unbind_my_electricity()`：解绑本人宿舍并清理关联提醒。
5. `set_my_electricity_reminder(value, unit)`：设置金额（元）或天数（天）预警，自动覆盖旧规则。
6. `get_my_electricity_reminder()`：查看当前提醒设置、推送目标会话及类型。
7. `disable_my_electricity_reminder()`：关闭本人提醒订阅。
8. `send_my_electricity_panel()`：直接在当前会话生成并发送七日电费图片看板。

## 5. 关键算法与架构机制

### 5.1 早间扣费预测放行算法（`settlement.py`）

重庆大学缴费平台在早间（09:00～14:00 之间）扣费时没有任何状态码指示。算法基于昨日 14:00 采集的“物理基准点”与今早 09:00 采集的“最新快照”，通过 `_settled_charge` 进行严格的数学特征核验：

```python
# 核心校验逻辑（摘自 settlement.py）
def _settled_charge(readings, cost):
    # 1. 资金项单调性校验：总额、现金、补助电量、补助金额全程不得出现任何上升
    for field in MONEY_FIELDS:
        # 若存在任意后一条记录大于前一条记录，说明发生了充值或补助发放，拒绝判定
        ...
    # 2. 扣费金额拟合度校验：余额减少额与电表耗电费用的偏差 <= 5% 或 0.05 元
    debit = _number(readings[0]["total_balance_yuan"]) - _number(readings[-1]["total_balance_yuan"])
    return debit > 0 and abs(debit - cost) <= max(Decimal("0.05"), cost * Decimal("0.05"))
```

- **已扣费状态（`state="settled"`）**：当且仅当资金无任何充值迹象且余额减少量与电表耗电费用吻合时，判定校方已执行扣除。此时 `estimated=False`，看板直接以**当前实际平台余额**预测剩余可用天数，**杜绝二次预扣**。
- **待扣费状态（`state="possibly_unsettled"`）**：如果资金项完全未发生任何变动，且电表读数正常增长，则进行一次假设预扣：`预计余额 = 平台当前余额 - (读数差 × 单价)`，看板今日节点使用预计金额与空心圆标记。
- **异常保护（`unavailable`）**：若发生金额变动但不符合耗电量规律（例如部分到账充值、退款或不可识别的抵扣）、电价变动或读数回退，则安全隐藏早间天数预测，避免误报。

### 5.2 09:00 / 14:00 错峰分段排程算法（`scheduler.py`）

为了避免多宿舍同时集中访问校方服务器引发的拥堵与频控，调度器采用确定性散列分段错峰调度：

```text
[09:00:00 / 14:00:00 批次触发]
       │
       ▼
计算每宿舍 SHA256("YYYY-MM-DD/HH:MM/<room_id>")
       │
       ▼
按哈希字典序排列宿舍队列，映射到 300 秒（5分钟）时间轴
       │
       ├─ 每步长 step = max(20.0, 300.0 / 宿舍总数)
       ├─ 段内微扰动 jitter = (hash[:4] % 11) 秒 (0~10秒浮动)
       └─ 相邻宿舍之间保证至少 10 秒硬间隔
       │
       ▼
写入 SQLite capture_plans 表（重启后保持既定排程，不重抽签）
       │
       ▼
若单个宿舍采集失败 -> 登记 retry_after 为 5 分钟后，允许重试最多 1 次 (attempts < 2)
批次截止前（午夜或下一批次前）未完成的任务标记超时，不突发追赶
```

### 5.3 采样断点后的近期基线回退机制

天数预测优先使用最新连续有效日间隔；当网络波动或接口故障造成断点不足最低数量时，算法启用稳健的近期基线回退策略：
- 采用 7 日滑动窗口内最近的完整连续段（虎溪至少 3 段、沙坪坝至少 2 段）；
- 该段的结束采集日距窗口末日不超过 3 天；
- 严格按实际采集物理时长加权折算日均用量，并用最新有效余额（上午适用时为预计扣费余额）估算天数；
- 缺日或非固定采集日的用量柱保持空缺，绝不进行虚假线性插值；电表回退、缺读数、电价改变及沙坪坝充值/补贴增加均不可通过回退跨越。

### 5.4 提醒推送的本人锁与去重机制（`reminders.py`）

1. **同宿舍同群合并**：同一群聊内同宿舍的多位室友若均开启了提醒，定时检查触发时会自动合并为一条消息发送，并精确 `@` 当天未被提醒的订阅者，避免刷屏骚扰。
2. **本人锁机制**：用户修改提醒、开启/关闭提醒或换绑时，对本人 QQ 加持异步锁；实际推送出队前二次校验绑定关系与阈值，防止已解绑或已关闭的用户收到旧提醒。
3. **自然日每日一次去重**：以自然日为界，持续低电状态下每个用户每日最多收到一次成功提醒，避免造成频繁打扰。

### 5.5 沙坪坝能源管理系统直连与多维统计机制（`client.py`）

沙坪坝老校区（A、B、C校园）全面支持免密直连校方能源管理系统（`nh.cqu.edu.cn:26989`），突破了原缴费平台缺少读数与历史数据的限制：

1. **免密账密解析与设备定位**：基于用户规范化房号（如 `B10S306`）发起登录认证获取内部账户标识 `SysLoginAcctID`，并发/串行调取账户金额（`/df/Home/GetAcctDs`）与电表设备明细（`/df/Home/GetSAcctDs`），直接提取电表物理累计读数与电价；
2. **今日用量动态区间累加**：实时调取最近 48 小时用电明细（`/df/Home/Get48GourDs`），自动过滤北京时间当日（00:00）起的全部 6 小时采样区间记录并求和，精确标注最新统计时间节点（如“今日零点至 06:00”）；
3. **自然月账单直读**：调取最近 12 个月账单详情（`/df/Home/GetDeBils`），直接读取校方最新月度账单的已用度数与核算总金额；
4. **数据库全字段持久化归档**：所有采集成功的今日与月度指标均自动随单次请求同步落库 SQLite `query_runs` 表（Schema 5 扩展列自动迁移），实现日度数据每日自动归档；
5. **双通道容错与优雅降级**：用电统计端点采用保护性容错处理；若能源管理系统发生网络超时或故障，且用户配置了缴费平台 Token，插件将自动平滑降级至缴费大厅接口，保证核心查询业务高可用。

## 6. 图片渲染环境（可选）

插件内置本地 Playwright HTML 渲染引擎，生成高清晰度看板与日历图片。**图片渲染环境为可选项**：
- 当宿主环境未安装浏览器或渲染失败时，插件会自动且平滑地降级为结构清晰的文字排版，查询、刷新与提醒等核心功能均正常可用。
- 若需开启图片看板，运行环境需满足：
  1. 安装 Playwright Python 库：`pip install playwright`；
  2. 安装 Chromium 及系统依赖：`python -m playwright install --with-deps --only-shell chromium`；
  3. 安装中文字体（如 Noto CJK 字库 `fonts-noto-cjk`），防止图片中文字符乱码或显示为空白方块。

### 容器化环境镜像示例 (`deploy/Dockerfile.dashboard`)

若通过 Docker 运行 AstrBot，可参考项目提供的通用构建示例：

```dockerfile
# Build on the exact AstrBot image already running on the deployment host.
ARG ASTRBOT_BASE
FROM ${ASTRBOT_BASE}
USER root
RUN uv pip install --system --no-cache playwright==1.55.0 \
    && python -m playwright install --with-deps --only-shell chromium \
    && apt-get update \
    && apt-get install -y --no-install-recommends fonts-noto-cjk \
    && rm -rf /var/lib/apt/lists/*
```

构建命令示例：

docker build --build-arg ASTRBOT_BASE=your-astrbot-image:latest -f deploy/Dockerfile.dashboard -t astrbot-with-electricity .
